Prepared 2026-10-18 for independent engineering and release acceptance. **Not published, tagged or deployed by this preparation.** The current published Stable/Latest release remains [v1.1.0](https://github.com/bokoboss/tmc-processor/releases/tag/v1.1.0).

Accepted implementation baseline: [`main@3f5a0f8e92893ac5f8b3174d47081d350a636133`](https://github.com/bokoboss/tmc-processor/commit/3f5a0f8e92893ac5f8b3174d47081d350a636133). ## Accepted changes since v1.1.0

- **Phase A — source integrity QC ([PR #45](https://github.com/bokoboss/tmc-processor/pull/45)).** Detect missing/duplicate intervals, malformed duration, quarter-hour misalignment and invalid/non-finite counts on report-included sources. Preserve original count/cell provenance and literal NA text. Blank counts are informational and remain visible in Single/Batch QC and exports without disqualifying clean Batch bulk acceptance. Excluded source sheets do not create actionable source-integrity findings. QC is advisory: no automatic interpolation, deletion or calculation-policy change. [Evidence](../development/EVIDENCE_DATA_INTEGRITY_PHASE_A.md).
- **Phase B — Excel import reuse ([PR #47](https://github.com/bokoboss/tmc-processor/pull/47), [Issue #46](https://github.com/bokoboss/tmc-processor/issues/46)).** One shared workbook-reader context; unchanged Single reruns reuse one session-local parsed payload keyed by actual content SHA-256 and parser revision. Replacement/clear, incompatible or corrupt cache entries invalidate safely; independent returned frames prevent mutation leakage. Retained payload is capped at 32 MiB; larger inputs still work without caching. No global/disk cache or new Batch cache. WorkflowState remains the readiness authority. Historical local benchmarks show zero workbook opens/parses on unchanged warm Single reruns; they are not production performance guarantees. [Evidence](../development/EVIDENCE_EXCEL_IMPORT_PHASE_B.md).
- **Issue #42 — V1 Native OOXML final PCU precision ([PR #48](https://github.com/bokoboss/tmc-processor/pull/48)).** Five final Summary cells use precise sources followed by one Excel-compatible rounding: F30/F31 use effective AM/PM Peak; F32/W40/AM22 use report-included Movement_Summary rows with dynamic V1 row bounds. Caches match Excel rounding. Source reconciliation rejects per-hour redistribution and duplicate canonical movement groups. The narrow hourly rounding exception does not relax individual-movement checks. Templates, HLOOKUP bindings, W40 shared-formula dependents, drawings/charts, precise calculations and V2 remain protected. [Implementation evidence](../development/EVIDENCE_ISSUE42_V1_PRECISION.md); the [accepted merge record](https://github.com/bokoboss/tmc-processor/commit/3f5a0f8e92893ac5f8b3174d47081d350a636133) supersedes its earlier pending GUI status.

For the two public V1 demo days, the accepted final values are:

| Demo | F30 AM | F31 PM | F32 / W40 / AM22 | Precise reported PCU |
|---|---:|---:|---:|---:|
| Day 1 | 2,981 | 3,153 | 23,959 each | 23,959.041 |
| Day 2 | 2,872 | 3,036 | 23,590 each | 23,590.054 |

Detailed movement/hourly integers retain their accepted independent rounding and can be non-additive relative to once-rounded final totals. No residual is allocated. The #42 correction covers V1 Native OOXML generation; Safe PNG and legacy Excel COM generation were outside that correction's scope. Recalculating an OOXML workbook through COM does not qualify legacy COM generation. The discrepancy documented for published v1.1.0 remains historical fact; Issue #42 is closed on accepted main.

## Known limitations and acceptance boundaries

- **Original Excel print pagination:** preserved template print settings can produce two A4 landscape pages. The accepted #42 GUI record verified Fit Sheet on One Page as a manual preview setting; the application/template defaults were not changed.
- **A4 print readability:** fitting the dense report onto one page can make text/charts too small. Default A4 readability remains a separate UX follow-up; neither a complete preview nor correct totals establish readable printed output.
- **Batch Project Session:** Save/Open remains disabled because the session format cannot round-trip Batch uploads and Batch Mapping Presets. Batch shares one preset for the same intersection across files; per-file mapping selection is unsupported. Single sessions do not embed source Excel uploads.
- **Excel compatibility:** qualification covers tested native V1/V2 packages and the recorded Microsoft 365 environment, not every Excel build, alternative spreadsheet viewer, workbook or printer. The #40 Cloud workbook opening rejection was not reproduced later; its original cause remains unknown. openpyxl's DrawingML read warning does not certify native-object rendering and is not a reason to resave protected native templates with openpyxl.
- **GUI qualification scope:** accepted #42 human inspection covered corrected V1 demo days and an unchanged V2 control, visible totals/charts, recalculation without errors, and one-page scaling preview. COM evidence used Excel 16.0 build 20430 with 33 shapes/two charts on native outputs. This is inherited baseline evidence, not a fresh GUI sign-off of every v1.2.0 package export, Excel version or printer. Candidate-specific results and unverified gates are listed separately in the release evidence. Hidden COM `Range.Text` can show `###`; the accepted GUI screenshots did not show that in final totals.
- **Candidate display/recalculation findings:** a fresh candidate V1 day-1 GUI smoke reproduced `###` in the final-total area at the observed 55% worksheet view; readable display/print acceptance must address this inherited width condition explicitly. Read-only COM opening, formula-error scans and all five recalculated totals passed for both native V1/V2 demo days. Safe PNG workbooks opened with no formula errors, but Excel's application calculation state remained pending; their complete COM recalculation is unverified. No export or template behavior was changed to hide either observation.
- **QC boundaries:** missing intervals outside selected Peaks that are absent in every included source cannot be inferred without a survey schedule. QC reports defects; operators must correct sources and re-analyze.
- **Peak contract:** supported Peaks are whole hours comprising four 15-minute intervals, explicitly confirmed in Review. Unsupported rolling legacy selections require re-analysis/confirmation; there is no automatic snapping.
- **Cloud acceptance:** published v1.1.0 had Cloud acceptance. Linux CI and local startup are not production Cloud acceptance of v1.2.0. The live deployment revision and candidate end-to-end Cloud workflow have **not been verified** by this release preparation. No deploy is authorized.
