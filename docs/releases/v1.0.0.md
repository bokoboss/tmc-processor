# TMC Processor v1.0.0

## Status
Stable closure release for the UX modernization program (UX-0 through UX-8).

After this release, the project enters maintenance mode. Future changes should be handled as focused bug fixes or separately accepted enhancements.

## Highlights
- Canonical five-stage workflow for Single and Batch: `Data -> Mapping -> Analyze -> Review -> Export`.
- Sheet-centric physical Mapping with derived movement codes.
- Explicit Peak Review with suggested, draft, and confirmed states.
- Exception-first Batch review with per-file Peak confirmation.
- Application/UI architecture split while preserving validated engineering behavior.
- Standard package-preserving OOXML native-template export when the confirmed/effective Peak is representable by the authoritative template.
- Safe PNG explicit alternative/fallback with no Peak rounding or coercion.
- Cleaner operator UI, stage indicators, next-stage guidance, and global Single Project Session controls.
- Historical Public Beta preserved as `v0.2.0` and branch `legacy/v0.2.0`.

## Known limitations
- Issue #23: native-template support for non-hour-aligned rolling 60-minute Peaks such as `08:15–09:15`. Until implemented, Standard falls back to Safe PNG while preserving the exact confirmed Peak.
- Batch Project Session remains disabled because the current session format cannot round-trip Batch uploads and Batch Mapping Presets.
- UX-8 final live Batch smoke used successful demo files; failed/excluded outcomes were not recreated live in that pass.
- The UX-6 `WorkflowContext` / `WorkflowOperations` dependency surface remains relatively broad; future work should avoid expanding it without architectural review.

## Maintenance policy
- `main` is the maintained current line.
- `legacy/v0.2.0` is preserved as historical source.
- Merged task branches should normally be deleted after acceptance.
- Release tags must not be rewritten.
- Changes affecting Mapping, Peak, QC, WorkflowState, Project Session, Batch semantics, or export behavior require regression evidence appropriate to the affected risk.
